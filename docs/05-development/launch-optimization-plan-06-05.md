# 早睡自救局 16 周可上线优化方案

## 摘要

- 上线目标：先 Android，上 Supabase/Postgres，完整对话 AI，免费限额，真实提醒，真实睡眠监听。
- 开发原则：先稳住现有闭环，再接云端和 AI；所有云端能力必须有本地兜底。
- 核心数据主线：`daily_cycles` 作为唯一每日闭环主表，本地 SQLite 与云端 Postgres 保持同构。

## 周任务拆分

### 第 1 周：产品与数据模型定稿

- 梳理现有页面、存储、状态流，明确哪些保留、合并、废弃。
- 定义正式类型：`DailyCycle`、`UserPreference`、`TodayReview`、`SleepRecord`、`AIConversation`、`SleepAudioSession`。
- 输出本地 SQLite schema 与云端 Postgres schema 草案。
- 明确“非医疗建议”“AI 安全边界”“睡眠监听隐私边界”文案。
- 验收：数据模型文档、状态流图、页面到数据字段映射完成。

### 第 2 周：统一每日闭环状态

- 以 `DailyCycle.status` 替代当前多套状态含义。
- 改造首页、自救、复盘、睡意生成器、准备睡觉、打卡、反馈页的状态推进。
- 增加 `feedback_viewed`，避免反馈页重复触发。
- 保留旧数据读取兼容，先不强删旧结构。
- 验收：完整 demo 流程状态推进稳定，重启后首页 CTA 正确。

### 第 3 周：本地 SQLite 数据层

- 接入 `expo-sqlite`，建立本地数据库、migration、repository 层。
- 将每日闭环、复盘、打卡、AI 会话、睡眠监听摘要迁入 SQLite。
- AsyncStorage 只保留轻量设置、首次进入标记、迁移版本。
- 增加旧 AsyncStorage 数据到 SQLite 的一次性迁移。
- 验收：清空、迁移、重启、断网记录都可正常运行。

### 第 4 周：API 客户端与离线同步框架

- 接入 `@tanstack/react-query`、网络状态检测、统一 API client。
- 定义 `ApiError`、重试策略、超时、失败提示和请求取消。
- 建立 pending sync queue：本地先写，联网后同步。
- 配置 `EXPO_PUBLIC_API_URL`，区分 dev/preview/production。
- 验收：断网可用，恢复网络后能同步队列，失败不会丢记录。

### 第 5 周：Supabase 基建

- 创建 Supabase 项目、Auth、Postgres 表、RLS 策略。
- 建表：`profiles`、`user_preferences`、`daily_cycles`、`today_reviews`、`sleep_records`。
- 先使用匿名用户或轻量账号进入，后续支持邮箱绑定。
- 前端完成登录态、token 安全存储、退出和删除账号入口。
- 验收：不同用户数据隔离，RLS 测试不串数据。

### 第 6 周：云端同步正式接入

- 本地 repository 增加 sync metadata：`local_updated_at`、`remote_updated_at`、`sync_status`。
- 实现配置、每日闭环、复盘、打卡的上传/拉取。
- 冲突策略：同一用户同一天记录以更新时间较新者为准，关键状态只允许前进。
- 设置页增加同步状态提示。
- 验收：换设备登录可拉取记录；断网编辑后恢复能同步。

### 第 7 周：AI 对话服务端代理

- 建 Supabase Edge Function：`/ai/chat`。
- 云端保存 `ai_conversations`、`ai_messages`、`ai_usage_limits`。
- 实现多轮上下文裁剪、每日消息限额、错误降级。
- 客户端树洞页从预设图改为真实对话 UI。
- 验收：AI key 不进客户端；超额限制生效；AI 失败有本地回复。

### 第 8 周：AI 睡意生成与安全边界

- 增加 `/ai/sleep-script`、`/ai/weekly-summary`。
- 睡意生成器支持根据晚睡原因、复盘内容、助眠偏好生成晚安暗示。
- 加入敏感内容兜底：不做医疗诊断，不承诺治疗，危机表达给安全提示。
- AI 输出保存为可回看记录。
- 验收：AI 内容语气符合产品，不越过医疗/心理治疗边界。

### 第 9 周：真实本地提醒

- 接入 `expo-notifications`。
- 实现开启/关闭提醒、修改提醒时间、修改提前量后重新注册。
- 防重复注册，清空数据和退出登录时取消提醒。
- 首页、自救页根据提醒设置显示真实状态。
- 验收：Android 真机提醒准时；重复保存不会产生多条提醒。

### 第 10 周：真实睡眠监听

- 接入录音能力，完成开始、暂停、停止、删除本机音频。
- 数据库只同步摘要元数据，不上传原始音频。
- 睡眠监听页明确权限、存储、删除、非医疗说明。
- 次日打卡页展示监听摘要。
- 验收：拒绝权限不崩溃；录音文件可删除；重启后状态一致。

### 第 11 周：原型图页面原生化

- `tree-hole`、`shutdown-challenge`、声音 Spa、周总结全部改为原生组件。
- 下线挑战实现真实倒计时、挑战动作、边界设置。
- 声音 Spa 先做模拟/基础音频播放，不接版权音频库。
- 验收：不再依赖静态热点图完成主流程。

### 第 12 周：成长页与反馈体验打磨

- 成长页基于云端/本地统一数据计算周变化。
- 周总结支持 AI 生成与本地模板兜底。
- 昨晚反馈增加“已查看”状态写入。
- 优化空状态、少数据状态、连续多天数据状态。
- 验收：成长页不是徽章墙，而是具体事实和长期正反馈。

### 第 13 周：稳定性、监控与埋点

- 接入崩溃监控和基础事件埋点。
- 埋点覆盖：onboarding 完成、自救开始、复盘完成、AI 使用、打卡完成、同步失败。
- 增加错误边界、加载态、失败重试和用户可读错误文案。
- 验收：关键错误可追踪，用户不会卡在空白页。

### 第 14 周：合规与安全

- 完成隐私政策、用户协议、AI 免责声明、睡眠监听权限说明。
- 检查 Android 权限：通知、麦克风、文件访问。
- 做 RLS 安全复测、删除账号数据清理、AI 日志脱敏。
- 准备商店素材：应用名、简介、截图、权限说明。
- 验收：上线审核材料齐全，敏感能力解释清楚。

### 第 15 周：Android 内测发布

- 配置 EAS production、versionCode、AAB 构建。
- 建立 internal test 包，跑完整真机回归。
- 修复内测反馈中的崩溃、同步、提醒、AI 限额、权限问题。
- 输出发布检查清单。
- 验收：内测包可稳定完成 3 天连续使用。

### 第 16 周：正式上线准备

- 冻结功能，只修 bug。
- 跑最终回归：离线、弱网、清空数据、删除账号、AI 超额、权限拒绝。
- 提交 Google Play 内部/封闭测试或正式发布轨道。
- 整理上线后监控看板和首周运营观察指标。
- 验收：生产包、数据库、AI、提醒、监听、隐私材料全部就绪。

## 测试计划

- 每周固定跑：`typecheck`、`lint`、核心流程手测、Android 真机回归。
- 数据专项：迁移测试、离线同步测试、RLS 权限测试、删除账号测试。
- AI 专项：限额、失败降级、敏感输入、长对话上下文、成本日志。
- 上线专项：权限拒绝、弱网、重启、清空数据、崩溃恢复、商店包安装。

## 假设与边界

- 第一版先 Android，不做 iOS。
- 第一版免费限额，不接支付。
- 第一版使用 Supabase/Postgres，不自建后端。
- 完整对话 AI 必须走服务端代理。
- 睡眠监听做真实本机录音，但原始音频默认不上云。
